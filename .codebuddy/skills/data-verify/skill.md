# 投研数据三源交叉验证

## 适用对象

- wiki md 中引用的财务数字（营收/利润/存货/渠道/IP 拆分/费用附注等）
- 验证前先明确三源角色：
  - **AKShare DB**（`data/<code>.db`）：结构化全期序列，快速比对锚点
  - **年报/中报 PDF**（`data/pdfs/<code>/`）：官方口径裁定者，附注级科目唯一来源
  - **用户提供 Excel / raw 资料**：第四源交叉，常有旧口径残留，不可直抄

## 流程五步

### 1. 建立参照系
- 导出 DB 关键表全期为临时文本：
  ```
  .venv\Scripts\python.exe -c "import sqlite3; conn=sqlite3.connect('data/<code>.db'); ..."
  先看 `SELECT DISTINCT report_date` 和 item_name 清单，再按期导出过滤行项
  ```
- pdfplumber 批量导出年报/中报全文为 txt（含页码标记），便于 grep 定位与反复搜索

### 2. 双向核对
- **md → PDF**：md 中每个具体数字（尤其千元级精确值）grep 定位到 PDF 原文行
- **DB → PDF**：DB 数字反向抽查年报损益表/资产负债表，确认口径一致
- **PDF 反查 DB**：官方摘要页金额应与 DB 对得上，不对上时查口径而非急着改数

### 3. 自洽性检验（快速定位错误区）
- 半年度 = 全年 − H1 倒算；分项加总 = 合计；区域跨表勾稽（如 IP × 区域 = 总收益）
- 费率反推：`数字/营收 ≈ 披露费率`（毛利率、物流费率、授权费率）
- ⚠️ 加总通过 ≠ 拆分正确——子项可能整体错位但总和恰好一致（本次实战实例：25H1 线上子渠道）

### 4. 判定铁律
- 每个数字必须找到 PDF 原文出处才算验证过
- **复现不出处的数字基本是错的**（无源百分比大概率是旧口径残留或编造残留）
- PDF 与 AKShare 冲突时：先查口径（总额 vs 净值、重述 vs 原披露），再判定谁错

### 5. 修正确证
- md 内留校注：`此前误录 X，YYYY-MM-DD 已按 <来源> 校正`
- 更新 `research-wiki/research/log.md`（日期 + 类型 lint | 标题 + 发现/修正清单 + 待跟进）
- 同类问题全局搜索清理（同一错误值可能被多处引用）

## 高危陷阱清单（实战沉淀）

| # | 陷阱 | 实例 |
|---|------|------|
| 1 | **净利三分口径混用** | 全面收益总额（含其他全面收益）/ 股东应占溢利（归母）/ 年内溢利（含少数股东）三者差可达 0.5 亿级，md 最易混抄 |
| 2 | **港股公司口径重述** | "中国内地"（24 年报原口径）vs "中国含港澳台"（25 年报重述）；跨年对比一律用最新年报的重述对比列 |
| 3 | **AKShare 口径漂移** | balance 表应收帐款有期为总额（含拨备）、有期为净值；对 PDF 以 Note 的净值/小計为准 |
| 4 | **单位换算错位** | 千元→亿元 = ÷100,000；千元→百万 = ÷1,000。10 倍/100 倍错位用费率反推暴露最快 |
| 5 | **Excel 用户表非可信源** | 季度拆分 sheet 可能有旧分类残留（如批发误归线上），只作第四源 |
| 6 | **附注级科目 DB 缺失** | 授权费、运输物流、IP/渠道子拆分、使用权明细等只能从 PDF Note 提取 |

## 工程注意点

- cmd 重定向输出到文件会用 GBK 编码，python 读回需 `errors='ignore'`；更稳妥做法是 python 内直接 `open(...,encoding='utf-8')` 写文件
- pdfplumber 打印 "Cannot set non-stroke color" 警告无害，忽略即可
- 大 PDF（300+ 页）全量提取约 10-30 秒，值得一次做完再全程 grep，避免反复开关
- 验证用的临时 txt 文件结束后删除，避免污染工作区

## 输出规范

- 结论分层：✅ 验证通过（列覆盖范围）/ 🔧 已修正（原值→新值→出处）/ ⚠️ 口径澄清（非错误）/ ❓ 待跟进（低风险未逐项复核）
- 不夸大覆盖面：明确哪些文档逐格验过、哪些只抽查
