# 深度阅读摘要

## 流程

1. 用 `scripts/extract_epub.py` 提取 epub 为临时 txt
2. **先粗读目录，锁定章节结构与行号范围**（search_content 定位章节标题）
3. **按章大块读取 → 立即成文**（见下方"读取与写作策略"）
4. 读取 `research-wiki/raw/research/articles/哈格斯特朗_2023_查理芒格的智慧-投资的格栅理论.md` 作为格式参考
5. 生成摘要，保存到 `research-wiki/raw/research/articles/作者_年份_书名.md`
6. 更新 `research-wiki/research/index.md` + `log.md`；如有 `generate_wiki_index.py` 则运行刷新 HTML 索引页

raw/ 里存的就是摘要，不存原文全文。不拆子页面。

## 读取与写作策略（防 token 浪费 / 防重读）

> 教训来源：2026-08-23《第五消费时代》入库时多次小步读取 + 反复补漏，导致上下文被压缩后被迫重读同一段，token 消耗巨大而效果未变好。以下为固化策略。

### 核心原则：大块读取 + 逐章立即固化

**不要通读完全书再回头写，也不要一小段一小段地读。** 而是：

1. **先粗读目录**：用 `search_content` 一次拿到全部章节标题 + 行号范围（如 `^第[一二三四五六七]章`、`^第N章`），画出全书骨架。这一步只读几十行，信息密度最高。
2. **按章大块读取**：每章用 1-2 次 `read_file`，`offset` + 大 `limit`（400-600 行）一次读完一整章。**避免 100 行以内的小步读取**——读得慢，前面内容容易被压缩清掉。
3. **读完一章立即写入摘要**：把该章内容固化进输出文件，不要留到全部读完后再补。已写入的内容不受上下文压缩影响。
4. **补漏用精准定位**：若确认某细节缺失，用 `search_content` 精确定位关键词 + `contextAround`，而不是大段重读原文。

### 具体执行要点

- **读顺序 = 写顺序**：按 目录→元信息→各章→后记 的顺序一边读一边写，避免回头。
- **每次 read_file 尽量读 400+ 行**，读到文件末尾为止（无需预判总行数，读到报错/EOF 即停）。
- **格式参考文件只读一次**：在动笔前读一次确认模板，之后不再重复读。
- **元信息（译者/出版社/ISBN）在开头一次性提取**，别写到一半再回来补。

### 明确"不重读"边界

- 已写入摘要的内容，**不得为了"确认"而重读原文**——除非该处摘要存在事实性疑问。
- 若上下文已被压缩导致记忆模糊，优先用 `search_content` 局部定位，而非整段重读。
- 同一段原文只读一次；若发现旧摘要缺内容，用精准搜索补，不整章重读。
