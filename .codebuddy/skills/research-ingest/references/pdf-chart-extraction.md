# 研报 PDF 图表数值提取（坐标吸附法）

> 适用：券商/投行研报 PDF 的图表承载关键数据（消费者调研、门店数、市场份额…），
> 正文只有结论性描述、数值在图上。
> 配套脚本：`scripts/extract_pdf_chart_values.py`（需 `pdfplumber`，本项目用 `.venv`）
> 本文件同时覆盖**公众号/网页文章的配图提取**（见第五节点——`web_fetch` 会丢图）。

---

## 一、先判定走哪条路

```bash
.venv\Scripts\python.exe .codebuddy\skills\research-ingest\scripts\extract_pdf_chart_values.py <pdf> --probe
```

| 探测结果 | 走法 | 说明 |
|---|---|---|
| `chars > 200`（有文本层） | **坐标吸附法**（本文档主流程） | 首选，可全量重建 |
| `chars < 50`（纯图片型） | **OCR（RapidOCR）** + 文字转写 | 图表数值通常**无法可靠配对**（OCR 按版面顺序输出），只能转写文字描述 |
| 图表无数字标签 / 折线图 | **不提取** | 逐图写「数值需回原 PDF」，不硬凑 |

## 二、坐标吸附法（有文本层）

### 步骤

1. **dump 单页看版面**（最关键的一步，别跳）
   ```bash
   ... <pdf> --dump 14 --y 440 600
   ```
   看三件事：① 图例（分组名）在哪一行、各列 x 是多少；② 数值在哪、是否与图例列对齐；
   ③ **有没有第二套标签**（左侧面板 label 与图内 label 顺序可能不同）。

2. **批量提取草表**
   ```bash
   ... <pdf> --pages 3-24 --columns Overall,China,Japan,US,UK,Australia
   ```
   脚本做三件事：按图例列 x 吸附数值（默认 ±14pt）→ 取该行标签（优先图内标签 x∈[300,392]）
   → 输出「标签 | 各列数值」草表。

3. **配对照正文交叉校验**（脚本不做判断，这步必须人工做）
   - **正文锚点**：正文里点名的数字必须能在表中找到（例：花旗 Fig 1「76% 一年内」= 23+22+19+12）
   - **加总校验**：单选类图表各档加总应 ≈100%（容忍 ±2pp，原文四舍五入）；多选题不适用
   - **跨题一致性**：同一事实在不同图/正文出现时应一致（例：持有 ≥2 件 88% vs 正文 88%）

4. **输出为表格**：只在表体放「选项 | 数值」，长句说明移到表下 `> ` 引用块。

### 参数（默认值已按花旗版式调好，版式不同时调整）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--col-tol` | 14 | 数值吸附到列的 x 容差（pt） |
| `--inner` | 300,392 | 「图内标签」x 窗口（紧贴柱形的标签） |
| `--inner-y` | 4 | 图内标签 y 容差 |
| `--outer-y` | 6 | 左侧长标签 y 容差 |

## 三、七个坑（都踩过，逐条对应实例）

1. **两套标签，顺序不同** —— 图里可能同时有「左侧面板标签」和「图内标签」，两者选项顺序不一样。
   **必须用图内标签**（紧贴柱形、x≈312），它与数值同 y。
   实例：花旗 Fig 12（用图内标签才与正文「Have other priorities 33%」吻合）、Fig 31、Fig 32。

2. **数值输出顺序 ≠ 轴顺序** —— 部分图（含 OCR 输出）按柱高降序排列，直接顺序配对会全错。
   实例：伯恩斯坦 Exhibit 10/11/13；花旗 Fig 32。**凡配对未经校验，不得按列表顺序引用**。

3. **水印遮挡** —— 中文水印（「订阅研报添加QQ群」「加微信…」）会压在标签或数值上，
   导致个别格子拿不到值。**不猜数**，该格写「—（水印遮挡）」并注明。
   实例：花旗 Fig 17 的 Overall 与 China 两格。

4. **双面板图** —— 「左＝整体条形图（常常没有数字标签）+ 右＝分组柱形图」是常见版式。
   数值只在右面板，表中取值后注明「取自右面板」。
   实例：花旗 Fig 24、Fig 32。

5. **折线图 / 无标签柱图** —— 文本层只有轴刻度与图例，没有数据点标签，**提取不出就是提取不出**。
   实例：花旗 Fig 23、36（柱值无标签）、Fig 37-40、42（周度折线）、Fig 41（双柱值散落）。

6. **小样本** —— 条件题基数可能极小（如「未来不买」只占 2% ≈ 30 人），百分比跳动极大甚至全 0。
   必须标注基数与「不宜作结论」。实例：花旗 Fig 33。

7. **原文自身矛盾** —— 正文叙述与图表不一致、或跨题基数不一致（同一群体两个比例逻辑上不可能）。
   **以图表为准 + 明确标注冲突**，不要替原文「圆」过去。
   实例：① 花旗 Fig 26 正文称「美国 59%」而图中美国 44%、英国 59%；
   ② 花旗 Fig 21 Tokidoki 中国 11% 与正文「中国重叠更高」不符；
   ③ 伯恩斯坦「34.04% 从未购买」与「29.08% 从未买非 LABUBU 产品」不能同时成立。

## 四、交付要求

- **图表一律表格化**，不写成行内散文（如「（图表数值：a% / b%…对应 X / Y / Z）」）
- **横纵按可读性择一**，不一刀切：
  - 选项为行、分组为列（调研交叉表默认形态，如花旗六国）
  - 档位 ≤6 且标签短 → 可转单行横表（如伯恩斯坦 Exhibit 7 年支出）
  - 档位 ≥7 且标签较长 → 左右分栏横表（4 列、先左后右）
  - 标签为完整句子 / 需带定义列 / 档位 ≥9 → 纵表
- **每张表下加校验注或存疑提示**（`> ` 引用块），表体不放长句
- **摘要同步重生成**：关键数据按校验后的表重写，**每条标注来源图号/页号**
- **入库备注**写明：提取方法、未能提取的图表及原因、原文矛盾点
- **宁标「待核」不硬凑**：未通过校验的配对不得当作事实写入

## 五、公众号 / 网页文章里的图表（web_fetch 会丢图）

> **适用范围（2026-09-20 用户定调）**：**可选，默认不做**。文章类资料首轮入库按纯文本处理即可；
> 仅当**用户明确要求**或**该图承载关键数据（正文没写、图上才有）**时，才执行本节流程。
> 研报 PDF 的图表重建（第二～四节）不受此限，仍按常规执行。

**症状**：`web_fetch` 返回的"完整原文"看上去完好，但**正文里的图表全丢了**（只回文本），raw 入库后这部分内容永久缺失（2026-09-20 实例：庶人哑士《关于AI应用的十个判断》正文唯一一张 Palantir 营收图，首轮入库时漏掉，用户追问"为什么不提取图表的内容？"才发现）。

**做法**：

```bash
# 1) 抓原始 HTML（带 UA；正文藏在 JS 变量里，URL 是 \x22 转义形式）
curl -s -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)" "<url>" -o _tmp_wx.html

# 2) 反转义后捞正文图片链接
#    decoded = raw.replace('\\x22','"').replace('\\x3c','<').replace('\\x3e','>')
#    re.findall(r'data-src="(https://mmbiz\.qpic\.cn/[^"]+)"', decoded)

# 3) 读图转写：数据图 → 表格；示意图/流程图 → 文字结构
#    需要看图时用不带 Referer 的请求下载到临时文件，转写完成后删除（默认不留副本）

# 4) raw 里只记两条链接：原文链接（已在头部元数据）+ 原图 CDN 链接
```

**默认不保存原图副本（2026-09-20 用户定调）**：图表**转写为表格即完成留证**，原图不落盘——保留**原文链接**（文章里图能正常显示）与**原图 CDN 链接**两条回溯入口即可。

**为什么不能内嵌微信图床链接**：`mmbiz.qpic.cn` 有 **Referer 防盗链（实测）**——Referer 非微信域名时（`file:///`、`localhost`、任意站点）返回 **HTTP 200 但内容是 2,090 字节占位图**（image/jpeg），**静默替换、不报错**。故该链接只能作**人工回溯入口**（浏览器地址栏直接打开 / 在公众号原文内查看），**不要写进 `![]()`**。

**要点**：

- **转写优先，转写完就达标**：数据图 → 表格（逐格核对见下）；示意图 → 文字结构。不需要为了"存档"再存一份图
- **例外**：**无法转写且内容关键**的图（实拍照、复杂示意图）才考虑下载，放 `research/<专题>/assets/`；raw 内引用用 `../../../research/<专题>/assets/x.png`，wiki 页在 `research/<专题>/<子目录>/` 下用 `../assets/x.png`
- 只有 1 张图也可能在 HTML 里出现 2 次（正文 + `picture_page_info_list`），**按 URL 去重**
- 若确实下载了图片：**得到约 2KB 的 jpeg 说明命中了防盗链占位图**（请求带了 Referer），改用不带 Referer 的请求重下
- 只有存在于正文 `<section>`/`mpa-common-...` 内的 `data-src` 才是正文配图；QR 码、作者头像、封面图不算
- **读图必须先放大校对**：把图切成 2–3 段、放大 2×～4× 再逐格看，别一眼扫图上数字（本项目已用此法避免读错标签归属）
- 图上没有标签的值：**标"（原图未标注）"**；可由相邻值 + 同比反推的，标 **"反推值"** 并写出算式；只能读轴的，标 **"目测"**
- 图的水印/来源要记（如 `理杏仁 lixinger.com`）——第三方数据图**不等于公司财报原文**
- 补录会写回已入库的 raw：属"只进"（补齐原文缺失部分，不删改原文），需在 raw 内标注**补录日期 + 逐格核对说明**，并同步摘要与 log
