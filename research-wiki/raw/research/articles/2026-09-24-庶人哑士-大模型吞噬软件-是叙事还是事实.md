## 摘要（3 分钟速读）

**一句话核心**：大模型吞噬软件**部分是事实、不完全是叙事**——应用层在"模型泛化能力 + AI Coding 降低手搓门槛"两头夹击下**正在变薄**，但传统软件厂商有**四条现实路径**把 AI 变成赋能而非吞噬；作者的结论是**"AI 不仅不会完全吞噬软件，反而在很多方面对软件有利"**，并从开发端/需求端/产品端/竞争端/商业模式/新品类六个维度列举了利好。

**核心论证链**
1. **软件的本质是工具**："通过指挥计算机干活，进而帮助人们更高效干活的工具"；传统软件是被动工具，AI 应用是"具有一定主动性、可以帮助完成某个任务的工具——你可以称之为**助理**"
2. **大模型与传统软件两点最大不同**：① 具备各种**泛化能力**（"软件百晓生"，对传统软件形成真实替代）；② 本身能**通过 Coding 生产软件**（中小用户手搓门槛与成本大降）。简单说即"**通百艺而专一长**"
3. **模型能干的活有四条共性**：判定标准清晰结果易验证 / 数据结构化、Context 轻 / 流程不复杂、时间跨度短 / 价值量大、ROI 高、值得重金投入
4. **为什么 Coding 最先爆**：四条共性基本都靠得上；接下来 AI 短剧、AI4S（Anthropic 自建湿实验室）只因**第四点**（价值量大）对得上，前三点"差点儿意思"
5. **路径判断**："**低垂的果子先被摘**，摘完一个再摘更高的果子时会更费力"

**关键事实与数据（原文口径）**
- 积极拥抱 AI 的公司名单（作者称来自最近几个季度电话会 + 行业调研）：美股 **Palantir、SAP、Salesforce、Hubspot、Workday、Datadog、Snowflake、Cloudflare**；港股 **迈富时、北森、美图、百融云、滴普、迅策、明略**——"**AI 对于它们不仅不是吞噬，反而是赋能**"
- 中小客户手搓软件的痛点：**维护责任不清、合规性差、兼容性差**；传统软件可把价格打到"手搓的 **2-3 倍**"但省掉所有维护成本
- 组织边界的比喻：陆地大象只能 **6~8 吨**，海洋蓝鲸可重达**上百吨**（引《深奥的简洁》《我从达尔文那里学到的投资知识》）

**四条现实路径（传统软件厂商拥抱 AI，原文编号）**
1. **从功能软件变成"业务AI的操作系统"**：Snowflake 把数据库变成 agent 的记忆与知识库；SAP / Salesforce 把每个 API 变成 agent 可调用的工具；Palantir / 北森把 RBAC 变成 agent 的操作边界；Datadog 把日志变成 agent 行为的可追溯证据
2. **深耕模型做不了的深度**：长周期状态管理（采购申请 发起→审批→下单→收货→质检→入库→付款→对账，跨数月、多人、复杂分支）是工作流引擎的活；概率生成器的**精确计算与一致性存疑**，需知识图谱/本体层等符号主义约束边界；行业 know-how 规则库（医保编码映射、人力资源科学、MES、WMS）是几十年积累的资产。最佳实践案例是 **Palantir**
3. **变成被集成的组件而非独立应用**：放弃完整前端界面，把自己变成被 Agent 调用的 API 服务（百融云风控 API）、被低代码平台嵌入的数据源与动作（飞书/钉钉/企微审批流调用北森人力逻辑与薪资考勤排班数据）、被 MCP/Function Calling 直接调用的工具
4. **往下沉市场走、往中小客户走**：提供"预置 AI + 预置流程模板 + 托管运维"一体化方案；作者坚信"**专业分工是效率最高、成本最低的方式**"，"客户手搓出来的是还凑合的玩具，不是真正的产品"

**六条 AI 利好软件（原文顺序）**
1. **开发端**：AI Coding 让成本大幅下降，"几乎体现在了所有我看过的上市公司的财报的人效指标中"
2. **需求端**：原本不具备经济性的内部流程被数字化、软件化；原来用不起软件的中小企业可以用了；IT 预算变成营销/人力/咨询预算，**TAM 扩大**
3. **产品端**：从死工具变成活同事、甚至决策顾问，服务更个性化更主动，**用户粘性增强、转换成本提高**
4. **竞争端**：无力拥抱 AI 的中小玩家出清，叠加中国 SaaS 两轮融资热潮后低谷期本身的供给出清，"行业龙头正面临前所未有的大好局面"
5. **商业模式**：由订阅制转为**积分或 token 消耗**，毛利率下降但营收暴涨——"**全栈Token工厂不再是叙事，而是在很多上市公司财报中真实发生的**"
6. **新品类创造**：AI 原生软件是新增量市场，"投资科技和消费品公司，就是要有'看见看不见'的能力，要有'因为相信，所以看见'的想象力"

**核心矛盾**
- **部分事实 vs 完全吞噬**：应用层确实在变薄（"**正视和接受这一点很重要**"），但"说大模型完全吞噬软件，是既不懂生态系统，又不懂分工协作"
- **无边界扩张不成立**：组织大到一定程度，内部管理成本会远高于外部节省的交易费用，"自然的'自临界法则'就不允许这样的庞然大物存在"
- **手搓的边界**：单人手搓的规模效应"始终赶不上服务多租户的专业厂家"，但中小客户确实在被分流

**投资策略结论（原文）**
> "当下的投资策略是：**想办法吃到前五类的红利，并积累对AI应用的know-how，保持对第6类机会的关注**。"

**局限提示（阅读时注意）**
- 文章通篇为**定性判断与投资框架**，未给出财务数据出处；"十几家公司管理层都这么说、行业调研也能验证"为作者自述，**未列具体电话会期次与引文**，引用前需回溯各公司业绩会原文
- 涉及具体公司（Palantir、Snowflake、SAP、Salesforce、Datadog、北森、迈富时、百融云等）的路径描述为作者归纳，非公司官方口径
- "手搓的 2-3 倍"定价、人效指标改善等为作者经验判断，**无量化出处**

## 正文（完整原文）

大模型的本质也是软件。

不管是本地部署（OP），云端部署（SaaS），传统软件通常都是具备某种功能的工具。它通常可以提高人们完成某项任务的效率。比如CRM可以提高销售跟单的效率，ERP可以提高业务数据存、管、用的效率，T云、珍客、HubSpot可以提高营销获客的效率。

从这个维度，可以抽离出软件的本质：它是一个通过指挥计算机干活，进而帮助人们更高效干活的工具。

沿着这条线往下推，传统软件和AI应用软件，没有啥本质的不同。传统软件无非是被动的、等待着人们去使用的工具；AI应用软件是具有一定主动性、可以帮助完成某个任务的工具--你可以称之为助理。

大模型这个软件与传统软件最大的不同有两点：一是具备各种泛化能力，二是本身能够通过Coding生产软件。简单说，就是"通百艺而专一长"。

大模型吞噬软件，也正是基于这两点。

和传统软件聚焦于某一项或几项功能不同，大模型具备极强的泛化能力，这让它变成了"软件百晓生"。无论是哪个行业、哪个领域，它多少都能懂一点，也能干一点活儿。这对传统软件形成了真实的替代。

另一方面，AI的Coding能力，让用户手搓软件的门槛和成本都大大降低。也确实观察到部分中小用户在这么做。

所以，模型吞噬软件确实部分是事实，不完全是叙事。应用层在两头夹击之下在变薄，正视和接受这一点很重要。

但如果我们再往深了挖一下，可以得出大模型能干的那些活儿的一些共性：

1. 判定标准清晰，结果易验证；
2. 数据高度结构化，不太依赖真实工作场景，Context轻；
3. 流程并不复杂，且时间跨度比较短，
4. 价值量大，ROI高，值得重金投入。

为什么Coding最先爆？因为上面四点基本都靠得上。为什么接下来是AI短剧？然后是AI4S？为什么Anthropic自己会花钱建湿实验室？因为第四点对得上，而前面三点都差点儿意思。

路径非常清晰：低垂的果子先被摘，摘完一个再摘更高的果子时会更费力。

传统软件厂商也没有闲着。你去听最近几个季度的电话会，会发现无论是美股的Palantir、SAP、Salesforce、Hubspot、Workday、Datadog、Snowflake、Cloudflare，还是港股的迈富时、北森、美图、百融云、滴普、迅策、明略，它们都在积极拥抱AI。AI对于它们不仅不是吞噬，反而是赋能。

如果只是一家这么说，可以不信。当中美两地十几家公司的管理层都这么说，行业调研也能验证的时候，还选择不信吗？

它们拥抱的姿势多种多样，有管理层的战略选择，也有公司自身禀赋的现实约束。从它们的动作中，可以总结出几个现实路径：

**路径1：从功能软件变成"业务AI的操作系统"**

Snowflake把数据库变成agent的记忆和知识库；SAP和Salesforce把每个API变成agent可调用的工具；Panlatir和北森把RBAC变成agent的操作边界；Datadog把日志变成agent行为的可追溯证据。

**路径2：深耕模型做不了的深度**

大模型不擅长的东西，恰恰是传统软件的护城河。这方面的最佳实践案例就是Palantir。比如长周期状态管理：一个采购申请从发起→审批→下单→收货→质检→入库→付款→对账，跨越数月、涉及多人、有复杂分支逻辑。这是工作流引擎的活，不是对话能解决的。

当下的大模型是基于连接主义的Transformer架构的概率生成器，完成任务的精确计算和一致性存疑，财务核算、税务申报、库存精确扣减——模型会"差不多"，业务要"分毫不差"。这时候需要知识图谱和本体层这种符号主义来约束行为边界。

通用大模型也缺乏行业深度规则（know-how）的理解。比如医保编码映射、人力资源科学、制造业MES系统执行、供应链WMS调度等等，这些规则库是几十年积累的资产。

**路径3：变成被集成的组件而非独立应用**

就像生态系统的角色多种多样，犀鸟可以和犀牛互相寄生一样。AI应用这个生态系统中，也有各种各样的生态位。

可以放弃做完整前端界面，直接把能力送过去给AI Agent调用，把自己变成：被AI agent调用的API服务（"帮我查这个客户的信用额度"→调用百融云的风控API）、被低代码平台嵌入的数据源和动作（飞书/钉钉/企微的审批流里调用北森的人力业务逻辑和薪资考勤排班数据）、被大模型MCP/Function Calling直接调用的工具。

**路径4：往下沉市场走，往中小客户走**

中小客户手搓的痛点是维护责任不清、合规性差、兼容性差。传统软件可以把价格打到手搓的2-3倍但省掉所有维护成本，提供"预置AI+预置流程模板+托管运维"的一体化方案。

我始终相信专业分工是效率最高、成本最低的方式。客户手搓出来的是还凑合的玩具，不是真正的产品。单人手搓的规模效应，始终赶不上服务多租户的专业厂家。

说大模型完全吞噬软件，是既不懂生态系统，又不懂分工协作。

没有谁可以无边界扩张，吃下一切。无论是过往的历史经验，还是第一性原理都支持这个判断。当一个组织大到一定程度，内部的管理成本会远高于外部节省的交易费用。自然的"自临界法则"就不允许这样的庞然大物存在。

确实无法理解的，建议可以去看一下《深奥的简洁》和《我从达尔文那里学到的投资知识》。企业组织作为一个活物，和自然界有着诸多相通之处。陆地上的大象为什么只能有6~8吨？而海洋里的蓝鲸可以重达上百吨？沙堆为什么堆到一定高度就会沙崩？

AI不仅不会完全吞噬软件，反而在很多方面对软件有利：

1. 开发端：AI Coding让成本大幅下降，这几乎体现在了所有我看过的上市公司的财报的人效指标中。
2. 需求端：原有不具备经济性的内部流程开始被数字化、软件化了，原来用不起软件的中小企业也可以用了，原来的IT预算变成了营销、人力、咨询等预算，TAM空间扩大了。
3. 产品端：从死工具变成了活同事，甚至是决策顾问，服务更个性化、也更主动，用户粘性增强，转换成本提高。
4. 竞争端：无力拥抱AI的中小玩家正在出清，竞争格局正在优化。叠加中国SaaS行业在经历了两轮融资热潮后低谷期本身的供给出清，行业龙头正面临前所未有的大好局面。
5. 商业模式：由订阅制转变为积分或token消耗，毛利率下降但是营收暴涨。全栈Token工厂不再是叙事，而是在很多上市公司财报中真实发生的。
6. 新品类创造：AI原生软件是新的增量市场。这可能是创业公司做出来的，也可能是现有公司跑出来的。它们会长什么样，我还不知道。但投资科技和消费品公司，就是要有"看见看不见"的能力，要有"因为相信，所以看见"的想象力。

未来随着模型能力提升、token成本下降、智能供给不再稀缺，一定会带来应用的繁荣。当下的投资策略是：想办法吃到前五类的红利，并积累对AI应用的know-how，保持对第6类机会的关注。
