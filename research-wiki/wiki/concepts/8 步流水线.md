# 8 步流水线

## 概述

`build.py` 是系统主入口，编排 8 步强制流水线。任何一步失败 = 阻断 = 不生成报告。不存在 `--force`。

```
python build.py <代码> [--cf N | --pb N] [--years N]
```

## 流水线步骤（2026-06-14 智能新鲜度版）

| Step | 操作 | 脚本 | 跳过条件 |
|------|------|------|---------|
| 0 | config 完整性检查 | — | — |
| 1 | 数据拉取 | fetcher.py | 股价新鲜 + 财报期同步 → 跳过 |
| 2 | 年报 PDF 下载 | pdf_downloader.py | ≥3 份 + 去年 PDF 已存在 → 跳过 |
| 3 | MD&A 提取 | extract_mda.py | 已提取年份 ≥ 最新 PDF 年份 → 跳过 |
| 4 | 营收拆分入库 | insert_revenue.py | revenue_structure 有数据 → 跳过 |
| 5 | config final 切回 | — | — |
| 6 | 指标计算 + 交叉验证 | engine.py | — |
| 7 | HTML 生成 | generate_report.py | — |
| 8 | 72 项数据完整性验证 | build.py | 失败降级 WARNING，报告仍生成 |

**默认行为**：`python build.py <code> --cf 15.0` 自动判断新鲜度，无需 `--fetch`。
`--fetch` 强制跳过所有检测，无条件全量重拉。

## Step 0: 确认页 — 🔴 强制

**确认页是流水线的最后一道人工把关，必须出现。**

显示字段：
```
企业名 / 代码 / 市场 / 行业 / 报表币种 / 数据年份 / 估值方法 / 历史PE(PB)参考 / 强制拉取状态
```

**估值倍数确定优先级**：
```
CLI --cf/--pb  >  DB meta 已确认值  >  用户交互输入（含历史PE/PB参考提示）
```

**2026-06-14 修复**：无论是否传 `--cf`/`--pb`，始终展示历史 PE/PB 参考数据。PE 优先用 AKShare 自带的 `PE_AVG` 字段（跨 A/H/美股兼容），不再依赖 BPS/EPS 交集。

## Step 4: 营收拆分（唯一需手动的步骤）

每只标的需要 `scripts/<code>/insert_revenue.py`。营收结构写入 `revenue_structure` 表。

## 阻断诊断

```
BUILD FAILED →
  ├─ Step 0: 补 config.py
  ├─ Step 1: 检查 AKShare 网络
  ├─ Step 2: PDF < 3 → HKEX 搜索参数
  ├─ Step 3: mda_text 提取失败
  ├─ Step 4: revenue_structure 空 → 手动 insert_revenue.py
  ├─ Step 6: engine 字段映射兼容
  └─ Step 8: validation.mismatches > 0
```
