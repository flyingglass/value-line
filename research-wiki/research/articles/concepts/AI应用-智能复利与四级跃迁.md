# AI 应用投资框架：智能复利与四级跃迁

> 收录日期：2026-09-20
> 来源：微信公众号「庶人投资笔记」，作者 **庶人哑士**，《关于AI应用的十个判断》，2026-09-19 发布

## 一、定义：两个核心概念

### 智能复利（AI 时代的网络效应）

| 时代 | 主导经济特征 | 飞轮 |
|---|---|---|
| 工业时代 | 规模效应 | 产量↑ → 单位成本↓ |
| 互联网时代 | 网络效应 | 用户 ↔ 用户 / 信息 / 商品 |
| **智能时代** | **智能复利** | **用户 ↔ 能力** |

回路：**越深入客户业务场景 → 越理解客户要什么 → Agent/LLM 学得越快、能力越强 → 用的人越多 → 越好用 → 越多人用**。

原文承认"智能复利"概念来自**曾鸣《智能：AI时代的商业、组织与战略的本质》**，作者自称"他是我的嘴替"。

### 四级跃迁（商业模式分层标尺）

```
土路        →  铺装路面      →  高速公路        →  AI 跑车飙起来
数据治理    →  落数据中台    →  本体层 Ontology →  AIOS（类 Foundry）
```

原文强调：**每往下一步，都代表商业模式的跃迁，估值范式都值得重构。** 这条线的用途是"评估当下这些应用公司到哪一层了"。

## 二、十条判断（浓缩）

1. **AI 真能降本增效** — 证据来自产业一线"用钞票投票的买家行为"，而非模型厂/云厂卖家秀
2. **企业端开始 FOMO** — 用 AI 不一定有优势，但不用一定有相对劣势
3. **用 AI 的前提是数字化** — 当下很多 AI 应用公司营收爆发式增长，其实来自**数据治理**
4. **LLM 的瓶颈是高质量私有数据** — 互联网可抓文本约 100T，清洗后可用于 pre-train 约 15T，极致挖掘最多 300T，"早都被用完了"；**只能让 LLM 成"穷翰林"，干不了"县令"式的活**
5. **比私有数据更稀缺的是真实业务场景** — ERP/CRM 是"定格照片"，没有从 A 到 B 的过程；不让 Agent 参与过程就"总有些隔靴搔痒"
6. **智能时代的网络效应是智能复利**（见上文）
7. **智能复利过了临界点会自我加强** — "天下武功唯快不破"仍管用，但飞轮从"用户与商品"换成"**用户与能力**"
8. **看 AI 应用不能只盯营收增长** — 要看**跑得快**（营收）+**做得深**（NDR）两个指标
9. **中国版 Palantir 的现实路径** — 数据治理 → 数据中台 → 本体层 → AIOS
10. **AI 应用是盘大肉，没有一家能通吃** — 见第四节三个子判断

## 三、核心验证指标：NDR（净美元留存率）

原文给出的判据：

- **营收增长** = 谁跑得快（拓展的用户场景多）
- **NDR（复购率 + 增购率）** = 谁做得深（长出用户离不开的能力）
- **"这就是典型的过了临界点自我加强的财务证据"**

原文引 Palantir 分部门 NDR（**未附出处，待核**）：

| 部门 | NDR |
|---|---|
| US Commercial | **150%** |
| Government 整体 | **146%** |
| Commercial 整体 | 113% |
| International Commercial | **103%**（拖累整体） |

## 四、第十条：三个子判断（分类法）

| 类型 | 特征 | 模型能力的作用是 | 例子（原文口径） |
|---|---|---|---|
| **a. 浅层工具型** | 只满足最大公约数的通用需求 | **被吞噬** | 美图、做 PPT 等 |
| **b. 深重型垂直** | 有私有数据 + 进得去真实业务场景 | **被赋能** | Palantir（"一座数据炼油厂，LLM 是超级饥渴的数据怪物"） |
| **c. 长尾细分** | 要做深做重但价值量不大，长不出 Palantir | 模型公司进不去 | workbuddy 类应用市场 |

对 c 类的关键判断：**应用市场最稀缺的能力不是"丰富"，而是"筛选判断"**——帮用户筛出与具体任务最匹配的 Agent/Skill。

## 五、中国版路径：两条渗透路线（难度不同）

| 路线 | 顺序 | 难度 | 说明 |
|---|---|---|---|
| **正向** | 先帮客户数据治理 → 借机落自己的数据中台 → 再卖各种业务 Agent | 较易 | "要致富，先修路，但又不能只是修路" |
| **反向** | 先把某个 Agent 卖进去 → 再渗透数据中台 | **难得多** | 例：迈富时营销 Agent、北森 HR Agent；**"换数据中台像高速换轮子，轻易不会换"** |

关键卡点：**本体层（Ontology）搭建技术不难，难的是对业务的深度理解**——取决于两件事：**客户配合度 + FDE 专业度**。

> 与本库关联：FDE（Forward Deployed Engineer，驻场工程师）由 **Palantir** 首创，是本框架的落地载体，见对话沉淀 `research-wiki/research/` 相关页（Palantir 未单独立库，待用户决定）。

## 六、怎么用这个框架（操作化）

1. **先分层再比较**：拿"四级跃迁"给候选公司定位，不要跨层级比增速——处在"数据治理"层的公司营收爆发，与处在"AIOS"层的公司不是同一门生意
2. **盯 NDR 不盯营收**：营收增长可能是 FOMO 驱动的一次性项目收入；NDR 才证明"智能复利"真在转
3. **问本体层而非模型能力**：技术门槛不在模型，在业务理解 → 关键变量是客户配合度与 FDE 专业度
4. **用三个子判断做排除**：浅层工具型先排除（会被模型吞掉）
